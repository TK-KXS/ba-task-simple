12  Architecture Decision Records (ADRs)

All internal components are TK platform services (no ADR needed). Each non-TK component the customer already owns requires an ADR documenting why it is retained and how it is accessed. Every external system is reached only through TK-Connect (SAP/POS/payment/marketplace), TK-Notify (SMS/LINE/email) or TK-Auth (AD).

ADR-01SAP ECC 6.0 (Finance) - retain; access only via TK-Connect (RFC/BAPI)SAP is the customer's finance system of record; refunds must post there. SiamMart explicitly does not want anyone touching SAP directly. TK-Connect provides a controlled adapter with retry, DLQ and reconciliation.Adds TK-Connect middleware (build + run cost). Depends on usable RFC (AS-11). Direct RFC from platform is refused even if credentials are offered.

Rule enforced in design (warning to customer). SAP, POS, payment and marketplace traffic flows only via TK-Connect. We will not implement a direct RFC connection from the application to SAP ECC 6.0, and will decline any SAP credentials offered for direct access — this protects SAP stability, keeps an auditable integration boundary, and is a condition of TK support. Any request to bypass TK-Connect must go through an ADR and a Change Request.
