1  Introduction

This pack is the solution architecture and workflow design for the SiamMart Returns (SMR) programme. It takes the agreed requirements in TK-BA-SMR-REQ-01 and turns them into a target business process and a compliant technical architecture on the TK platform. Its audience is the SiamMart steering group (business, Finance, IT) and the TK delivery team.

1.1  Purpose & scope of this document

  • Redesign the process. Model the current ("As-Is") returns process exactly as it runs today and quantify its pain (§2–§3), then design a target ("To-Be") process that removes manual handoffs (§4–§5).
  • Design the solution. Specify the system context, the containers and services, the key integrations, the state model and the data model with PDPA classification (§6–§10).
  • Prove compliance. Show how every component is a TK platform service (or has an ADR), how money flows are idempotent/audited/reconciled, how PDPA is honoured, and how peak load is sized (§11–§14).

1.3  Architecture principles applied (mandatory)

  • Layering: Channel → TK-Gateway → domain services → TK-Database/TK-Storage. Channels never touch a database; cross-domain integration is via API/event only, never cross-schema SQL.
  • External systems only via TK-Connect: all SAP / POS / marketplace / payment traffic flows through TK-Connect. Direct RFC to SAP is refused even if credentials are offered.
  • Money flows are idempotent (idempotency key) and reconciled daily; every approval and status change writes to an immutable audit log.
  • Auto-approval of money is a configurable TK-Flow DMN rule whose threshold can be changed — or set to 0 — without deployment; it requires the customer's Finance/Audit written sign-off.
  • PDPA: every entity is classified (Public / Internal / Confidential / Personal / Sensitive Personal); personal data is encrypted in transit and at rest, masked in logs, and governed by a retention + deletion job.
  • Peak sizing: sized for 11.11/12.12 (4–5× baseline); TK-Queue absorbs bursts; headroom ×1.5.

2  As-Is Process
